Executive Summary

This audit delivers an exhaustive technical assessment of the Supernova 3.0 codebase and its cloud infrastructure before embarking on future feature implementations.

OFFICIAL BACKEND VERDICT: OPTION C

"Supabase is connected, but most backend functionality still needs development."

  • Frontend Experience (10/10 Completeness): The public website and administrative interface are visually stunning, responsive, conform strictly to design tokens, and execute without runtime errors.
  • Backend Reality (Partially Connected / Simulated Layer Active): While Supabase is live and queries return 200 OK for existing tables (event_settings, games), the database schema is missing 8 essential relational tables (such as teams).
  • The In-Memory Proxy Mask: In src/lib/supabase.ts, a resilient JavaScript proxy (createResilientClient) catches all failed database calls, uncreated tables (PGRST205), and RPC permission errors, silently serving and persisting mutations to client-side RAM (initialStore). Mutations look successful in the UI but vanish upon page reload.
  • Authentication: The /admin/login page provides quick-access demo credentials that bypass Supabase Auth entirely by creating artificial mock JWT sessions in browser localStorage. Real users do not yet exist in auth.users.

1. Frontend Audit

The frontend application is built on React 18.3.1, Vite 6.0, TypeScript 5.6, and Tailwind CSS v4. Layout discipline is strictly enforced using two mutually exclusive layouts:

  • PublicLayout: Floating glass navigation pill, section anchor scrolling, and comprehensive institutional footer.
  • AdminLayout: Dedicated administrative shell with sidebar navigation. Public navigation and footer elements are strictly prevented from rendering.

5. Database Requirements (Schema Checklist)

The following SQL migration must be executed in Supabase SQL Editor to bridge the missing tables:

-- 1. Create Teams Table
CREATE TABLE public.teams (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    game_id UUID REFERENCES public.games(id) ON DELETE CASCADE,
    name TEXT NOT NULL,
    captain_name TEXT NOT NULL,
    captain_email TEXT NOT NULL,
    captain_phone TEXT NOT NULL,
    institution TEXT,
    status TEXT NOT NULL DEFAULT 'pending',
    seed INTEGER,
    created_at TIMESTAMPTZ DEFAULT NOW()
);

-- 2. Link Players to Teams
ALTER TABLE public.players 
ADD COLUMN IF NOT EXISTS team_id UUID REFERENCES public.teams(id) ON DELETE CASCADE;

-- 3. Enable Public Anonymous Submissions
ALTER TABLE public.visitor_registrations ENABLE ROW LEVEL SECURITY;
CREATE POLICY "Public visitor registration insert" 
ON public.visitor_registrations FOR INSERT TO anon WITH CHECK (true);

ALTER TABLE public.teams ENABLE ROW LEVEL SECURITY;
CREATE POLICY "Public team registration insert" 
ON public.teams FOR INSERT TO anon WITH CHECK (true);

-- 4. Grant Admin RPC Access
GRANT EXECUTE ON FUNCTION public.is_admin() TO authenticated;

7. Immediate Action Plan

Action 1: Run Database Schema Migration

Create the teams, faqs, and registration_controls tables in the Supabase SQL editor.

Action 2: Provision Real Admin in Supabase Auth

Create an authenticated admin user in Supabase Auth and assign their UID to user_roles with role admin.

Action 3: Enable Public RLS Insert Policies

Allow anonymous website visitors to submit visitor registrations and tournament team applications without requiring a login.

Action 4: Connect Registration Forms Directly to PostgreSQL

Update the registration action handler to write to visitor_registrations and teams, retiring the memory mock.

Action 5: Provision Supabase Storage Bucket

Create the gallery-media storage bucket so admin photo and sponsor logo uploads persist to cloud storage.
